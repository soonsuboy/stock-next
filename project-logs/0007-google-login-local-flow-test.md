# 0007 - Google login local flow test

## Request

- Test Google signup/login after the user added Google OAuth information.

## What Was Checked

- Confirmed these local env keys are present without exposing secret values:
  - `AUTH_SECRET`
  - `AUTH_URL`
  - `AUTH_TRUST_HOST`
  - `AUTH_GOOGLE_ID`
  - `AUTH_GOOGLE_SECRET`
- Confirmed `/api/auth/providers` lists only Google because Kakao credentials are still empty.
- Confirmed `/api/auth/csrf` returns a CSRF token and auth cookies.
- Sent a CSRF-protected POST to `/api/auth/signin/google`.

## Result

- Google provider registration is working.
- The CSRF-protected sign-in request returns `302 Found`.
- The redirect target is Google's OAuth authorization endpoint.
- The redirect URI generated by Auth.js is:
  - `http://localhost:3000/api/auth/callback/google`

## Remaining Manual Step

- Complete the final login in a browser by clicking `Google로 계속하기` on `/login`.
- The assistant cannot complete the Google account consent screen without the user's Google session and approval.

## Notes For Next Agent

- A direct GET to `/api/auth/signin/google` can route back to `/login?error=Configuration`; the real flow is the login page form/server action or CSRF-protected POST.
- For local testing, Google Cloud Console must include:
  - JavaScript origin: `http://localhost:3000`
  - Redirect URI: `http://localhost:3000/api/auth/callback/google`
- For Vercel testing, use the deployed origin and `/api/auth/callback/google`.
